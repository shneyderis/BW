# Облікові дані Beykush Winery — нормалізована структура

Мета: привести дані з 1С до ладу згідно з вимогами бухобліку України
(План рахунків — Інструкція Мінфіну № 291 від 30.11.1999, НП(С)БО) і підготувати
їх до міграції в майбутню бухгалтерську програму (ще не обрано).

## Файли

| Файл | Що це | Звідки |
|---|---|---|
| `audit.py` | Аудит якості даних: друкує звіт, `--csv <dir>` пише таблиці проблем | читає `data/1c_*.csv` |
| `build_export.py` | Конвертер сирих даних у нормалізовані CSV | читає `data/1c_*.csv`, пише `export/` |
| `AUDIT_<дата>.md` | Знімок звіту аудиту | результат `audit.py` |
| `export/*.csv` | Нормалізовані дані для міграції | результат `build_export.py` |

Запуск (з кореня репозиторію): `python3 accounting/audit.py` та `python3 accounting/build_export.py`.
Залежностей немає — стандартний Python 3.

## Формат експорту (узгоджено для будь-якої бухпрограми)

Усі файли: CSV, кодування UTF-8 з BOM, роздільник — кома, дати — ISO 8601 (`2026-04-02`),
десятковий роздільник — крапка, суми у грн з 2 знаками. Кожен запис журналу має
поле `flags` — перелік знайдених проблем (`dup_doc_no;no_purpose;…`), щоб їх можна
було відфільтрувати й розібрати ДО імпорту.

### Довідники
- **organizations.csv** — `org_id, name, full_name, edrpou, kind, contour, note`.
  Юрособа одна: ТОВ «Бейкуш Вайнері» (ЄДРПОУ 37992910). «Бейкуш Ф2», «Интернет
  магазин», «Дегустации» — внутрішні контури (`kind=internal_contour`), НЕ юрособи.
- **counterparties.csv** — дедуплікований довідник: `counterparty_id` (K+ЄДРПОУ або
  KNxxxxx), канонічна назва, ЄДРПОУ, вид, податкова схема, `flag`
  (`merged_by_edrpou` / `merged_by_name` / `edrpou_conflict` / `auto_from_journal`),
  `alt_names` — усі варіанти написання, що злиті в одну картку.
- **products.csv** — номенклатура: `base_wine` (вино без вінтажу) + `vintage` окремим
  полем, штрих-код, од. виміру, ставка ПДВ, код УКТЗЕД для ПН; `flag=dup_sku` —
  кілька карток на один штрих-код.
- **warehouses.csv**, **staff.csv**, **contracts.csv** — як у 1С, з ISO-датами і `counterparty_id`.

### Журнали
- **sales_journal.csv** — продажі: `date, doc_no, org, contour, counterparty_id,
  counterparty_name, warehouse, amount_uah, currency, manager, comment, flags`.
- **bank_journal.csv** — банк: `date, direction (in/out), amount_uah, counterparty_id,
  counterparty_name, op_type, purpose, org, bank_account, flags`.

### Облік
- **chart_of_accounts.csv** — рахунки Плану № 291: які використовуються, яких бракує і чому це проблема.
- **trial_balance.csv** — ОСВ з назвами рахунків (сальдо/обороти).
- **issues_edrpou_conflicts.csv** — один ЄДРПОУ на різних осіб (помилки вводу, розібрати вручну).

## Головні висновки аудиту (деталі — AUDIT_*.md)

1. **1С вівся як торговий облік, не бухгалтерія**: проводились лише продажі та
   надходження грошей. Списання з банку — 0,1 % від надходжень, тому сальдо
   рах. 31 «віртуальні» ~74 млн грн.
2. **Немає цілих ділянок обліку**: ОЗ (10/13), запаси та виробництво (20/23/26),
   постачальники (63), зарплата (66/65), капітал (40/44). Для виноробні критично:
   собівартість вина не рахується ніде.
3. **Період не закривається**: 70/71/90/92 висять із сальдо, 79 не закрито на 44,
   рах. 92 має від'ємне сальдо (груба помилка), рах. 00 — із залишком.
4. **Чотири «організації»**, з яких юрособа одна; ~25 млн грн продажів проходить
   через внутрішні контури. Для міграції кожен контур позначено полем `contour`.
5. **Довідники засмічені**: 51 % контрагентів без ЄДРПОУ, дублікати карток,
   171 контрагент у продажах без картки в довіднику; одне вино — до 10 карток
   номенклатури; 99 % банківських операцій без призначення платежу.
6. **Розбіжності продажі↔оплати**: переплати ~3,4 млн грн (ознака непроведених
   накладних), борги ~7,1 млн грн; одна банківська операція з майбутньою датою
   (15.12.2026, 200 тис. грн).

## Що потрібно від майбутньої бухпрограми (чекліст вибору)

1. Український план рахунків (№ 291) і закриття періодів (70/90→79→44) «з коробки».
2. Імпорт довідників та журналів із CSV/Excel (ці файли) або через API.
3. Виробничий облік: 23 → 26 (виноробня: собівартість лоту/розливу), партії/вінтажі.
4. Зарплата та ЄСВ (рах. 66/65) або інтеграція із зарплатним сервісом.
5. ОЗ й амортизація (10/13).
6. Валютні операції (експорт: EUR/USD, курсові різниці, рах. 71/94).
7. Акцизний облік алкоголю (ліцензії, акцизна марка) — специфіка галузі.
8. РРО/ПРРО для каси й інтернет-магазину; ПДВ: податкові накладні, ЄРПН.
9. Кілька фірм/контурів в одній базі (ТОВ + ФОП-и), консолідація.
10. Поширені в Україні варіанти: BAS Бухгалтерія, MASTER:Бухгалтерія, Dilovod,
    «Облік SaaS» тощо — фінальний вибір за бухгалтером; ці CSV підходять для будь-якої.

## Порядок наведення ладу (рекомендація)

1. Розібрати `issues_edrpou_conflicts.csv` і картки `flag=edrpou_conflict` / `auto_from_journal`.
2. Закрити переплати/борги з `audit.py` (звірка з контрагентами, акти звірки).
3. Провести інвентаризацію: склад (пляшки), бочки (lots.csv), каса, банк — зафіксувати
   реальні залишки на дату переходу.
4. У новій програмі ввести початкові залишки на дату переходу (не переносити історію
   проводок 1С як є — вона неповна), а журнали з `export/` зберегти як архів-деталізацію.
5. Далі вести: видатки банку з призначенням, зарплату, виробництво, амортизацію.
